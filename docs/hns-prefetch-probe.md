# HNS prefetch qualification scope

The Electron 44.10.0 first-document experiment intermittently loses all DNS-prefetch hints in a guest, including distinct hints inserted after that document finishes loading. The retained observations suggest a Chromium connection-lifetime problem, but its native cause is unproven and no engine fix has been adopted. DNS hints are advisory. The upstream report remains local.

The first HTTP navigation still happens immediately. Its document identity, ordinary image lookups, protected listed-root refusals and absence of protected hint lookups remain checked. Its positive hint observations are diagnostic and cannot satisfy a release control. Results explicitly record `firstDocumentMatchedHintCoverage: unproven`. A green run does not establish matched first-document hint suppression or an upstream repair. The workspace_owner explicitly approved this coverage boundary on October 28.

Qualification uses the second document before theme changes and a third afterward. DNS capture begins before navigation so response-header hints are included. After both normal and private guests finish loading the expected documents, they stay alive and unchanged for the full existing fifteen-second observation interval. Before/after document and frame snapshots must match, and no navigation event may occur during the interval. Each round freezes its own results before any theme change or next navigation. The control process must resolve all six header/HTML hints in both guests in both rounds. No private-guest allowance, replacement hint, manually resolved name, retry or longer timeout can supply a missing control.

The protected process must produce no header, HTML or diagnostic hint lookup during the entire probe. Listed-root and `.pirate` zero-DNS assertions cover its page/guard phase and any later request with the probe's unique page-name prefixes; the earlier before-discovery baseline deliberately resolves a listed-root name. Ordinary image lookups, guarded navigation refusals, exact document/frame/session identity, and observed light/dark propagation remain mandatory. Waiting after a guest has been destroyed supplies no live-document suppression evidence.
