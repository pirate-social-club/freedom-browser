# Session routing quarantine

Routing remains a main-process responsibility. The proxy controller owns durable state for each Electron Session. The routing coordinator owns shared PAC and HNS guard preparation. The shared request dispatcher observes the controller through a stable synchronous getter. Window owners still await certificate and proxy enrollment before navigation. Read-only status IPC lets the renderer explain refusal; it grants no routing authority and adds no dependency.

The default session explicitly adopts its native startup state. This permits startup without claiming a DIRECT configuration receipt. New sessions start denied. A changed routing intent withdraws session permission and guard admission synchronously, before shared preparation. Identity includes the helper generation, certificate fingerprint, root resolver, namespace roots and dVPN endpoint.

For a changed policy the coordinator closes tracked old guard operations, prepares the captured route and PAC, applies native proxy settings, reloads them and closes connections. It retires obsolete resources before committing readiness. Every native application attempts connection closure even after configuration or reload fails. Settled failures remain quarantined and require a complete successful recovery. A failed shared preparation clears its cached policy; enrollment cannot repair shared resources while other sessions use an older policy.

An unchanged, valid policy preserves connections. Enrollment applies that policy only to the new session. Retirement is permanent for an Electron Session object. A retained getter cannot authorize its reuse. Registration tokens and monotonically increasing generations prevent delayed native completion or request callbacks from publishing superseded permission.

Configuration, reload and connection closure each have a 15-second deadline. Shared preparation and retirement have 30-second deadlines, including a separate 15-second guard-drain deadline. These timers observe completion while the main event loop responds. They cannot cancel native calls or stop a frozen process. A timeout therefore retires all session permission and invokes immediate Electron exit with code 70. Failed native connection closure or unconfirmed guard destruction also invokes that boundary after independent Electron drainage is attempted. This path does not await normal helper shutdown, which can enqueue routing on the same queue. It does not establish that external helper processes stopped.

The HNS guard has persistent admission control and tracks downstream sockets, CONNECT upstream sockets, HTTP requests, response streams and their upstream sockets. Downstream cancellation destroys paired operations. Actual close events settle drainage; calling destroy alone is insufficient. HTTP forwarding uses an unpooled, request-owned agent. PAC retrieval is outside this tracker and retains its existing URL during updates. Guard admission reopens only when the policy commits.

Source tests exercise failure ordering, permanent retirement, delayed completion, unchanged enrollment, deadlines and socket cancellation. They do not prove Electron's native connection closure stops HTTP streams or WebSocket traffic. Installed acceptance must cover those streams, PAC reload while the request guard is withdrawn, failed drainage followed by process exit, and resource identity. The shared Node guard does not identify the originating Electron Session, so a per-session receipt cannot claim direct attribution of every Node operation. Ordinary Mullvad acceptance, a full restart, secure Spaces origins and site-key binding remain separate work.

The existing HNS helper still updates certificate callbacks before withdrawing routing on readiness. Partial certificate installation failure needs its own withdrawal and recovery integration. This change establishes the proxy controller's contract; it does not establish containment of every certificate transition.

## Visible explanation

A quarantined session displays an explanation over the active guest in the already loaded browser UI. The guest remains hidden even when ordinary load-error handling tries to reveal it. Status snapshots contain only session state, generation and owned guest identifiers. The main process requires a live registered browser main frame at the exact installed index document, permits its existing initialUrl query and includes only actual guests belonging to that host. Remote pages and subframes cannot read status. Increasing revisions reject stale replies. There is no file, loopback or error-page exemption in the request guard.

If startup, reload or a renderer failure leaves no functioning trusted UI, a native asynchronous notice explains quarantine. Status delivery resumes when an unresponsive renderer recovers. A guard cancellation preserves the requested page even before the first status snapshot arrives, and requests a fresh observation without scheduling a replacement navigation. Observer and dialog failures cannot alter permission. The screen neither recovers the route nor automatically retries the failed navigation. Successful main-process recovery removes it; the user may then reload the requested page.

Terminal exit records a fixed reason code and a random acknowledgment identity in the migrated profile. It stores no URL, exception text or history. On the next launch a native asynchronous notice explains that Freedom closed to protect traffic and that unsaved work may have been interrupted. Startup awaits acknowledgment before starting routing producers, so a repeated failure cannot immediately remove the explanation. External freedom protocol links remain queued until browser initialization finishes, including while the dialog waits. The fatal handler itself does not await anything. Acknowledging an older notice cannot erase a newer event. Disk or dialog failure can prevent this best-effort notice. Synchronous filesystem I/O and a stalled event loop still prevent a hard exit deadline.

## Installed terminal acceptance

The hosted installed test must inventory the browser and its owned helpers before inducing a runner-controlled native or resource failure. Record executable bytes, PID and start time, ancestry, cgroup and listening sockets. The production application must not acquire a debug IPC or environment switch for fault injection. Prove exit code 70, disappearance of the browser and renderers, the next-launch notice with the same profile, and final controls. Preserve diagnostics on failure.

Inspect surviving owned helpers before any runner cleanup. Cleanup performed by the runner does not establish that Freedom stopped its helpers. Reused external nodes are outside its ownership and must not be terminated. An independent bounded helper-shutdown path remains to implement if owned helpers survive. This installed exercise, real streams, WebSockets, PAC reload and ordinary Mullvad acceptance have not yet run for the feedback change.
