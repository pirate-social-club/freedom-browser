# Encrypted HNS transport validation

The PR39-only hosted workflow builds pinned hnsd a5c7c287 with outbound libunbound TCP support for the loopback relay, truthful TC flags for oversized native replies, and SERVFAIL refusal of results libunbound marks bogus. The original and patched source archives, patch, compiler, system packages, license texts, ELF observations and native digest are retained. This dynamic build requires the target runtime's libunbound8; no system library is bundled.

The Node relay supplies authenticated Pirate HTTPS transport beneath the owned native validator. Root questions, top-level DS and local metadata stay on the owned authoritative root. Remote AD is cleared. Remote root authority is refused in every section. No plaintext external fallback is enabled. The native authoritative and recursive listeners remain UDP-only; oversized final answers fail closed.

Native fixtures run as an ordinary UID with loopback-only networking, one CPU, bounded memory, no swap and a finite deadline. The fixture injects DNS wire replies at the HTTPS request boundary; it does not test an external HTTPS connection. It exercises the real native validator with locally signed synthetic root delegations, a delegated child, large intermediate DNSKEY responses, corrupted DNSKEY/address signatures, TLSA and oversized final responses. These fixtures establish engine and transport behavior; they do not establish Handshake consensus, website availability or Mullvad compatibility.

The original Go helper can orphan its separately grouped native child when killed during startup. The packaged static wrapper writes a generation-specific process receipt with shell builtins before exec. Browser teardown stops Go first, verifies the native identity and UID, and waits for verified native exit. Missing or ambiguous receipts leave persistent unresolved custody and block new generations, including after a browser restart. The Linux proc identity check followed by signalling is not an atomic pidfd operation. The launch does not permit daemonization or fork mode.

Final package adoption requires independent artifact review, exact native manifest/source binding, target runtime linkage and licensing reconciliation. Installed browser acceptance, full restart, VPN-on navigation and DNSSEC/DANE negatives remain separate gates. No tag or release is created by this workflow.
